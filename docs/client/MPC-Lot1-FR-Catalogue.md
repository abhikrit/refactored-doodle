# Malawi Post — Lot 1 functional requirements (FR-001…FR-350)

Source: `MPC_Bidder_Response_Filled_with_SRS_References.docx`, "MPC Requirements Catalogue Annex,
Deliverable 2 — Lot 1 Functional Requirements". 350 requirements, one table, ten columns.

The shall statements are already in `docs/compliance/Compliance-Traceability.md` as
`REQ-MPC-FR-nnn` (338 of 350 word-for-word identical; the other 12 differ only in typography).
What that report does **not** carry, and this file does, is the four columns below:

| Column | Why it matters |
|---|---|
| Actor/Role | the client's own role per requirement - the authoritative role cut for Malawi Post |
| Module/Domain | the client's own 14-domain grouping, 25 requirements each |
| Acceptance criteria | **the client's** acceptance criteria, which are what a demo is judged against. They are not the product's AC-<AREA>-nnn and do not replace them |
| Priority | the client's MoSCoW, which is not the same field as the product backlog's priority |

The bidder response and comments are also carried: they are the commitment already made to
Malawi Post, so a requirement answered "Available" that the PRD routes as code-level is a
discrepancy worth seeing, not a detail.
